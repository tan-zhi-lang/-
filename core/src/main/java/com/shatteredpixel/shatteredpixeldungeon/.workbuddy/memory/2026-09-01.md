- 气团边框功能设计：本工程无 BlobSprite 类，气团渲染实际在 effects/BlobEmitter.java（GameScene.addBlobSprite 调用）。方案：Blob.java 增加 borderColor(默认0=不显示) 与 evolveVersion 字段，act/seed/clear/fullyClear 时递增版本；BlobEmitter.update 检测版本变化后按 blob.cur 计算边界单元格（四邻为0/越界即边界），用 TextureCache.createSolid 生成的 Image 池绘制 1px 边框，可见性沿用 heroFOV||alwaysVisible 逻辑。边框随每回合 evolve 自动重建。
- 已落地：Blob.java（字段+4处 evolveVersion++）与 BlobEmitter.java（边框渲染）均已改写完成，GameScene 无需改动；各 Blob 子类在实例块设置 borderColor 即启用。
- 坑：本 fork 的 noosa（D:\-\SPD-classes）Visual 无 size(float,float) 方法，Image 尺寸须直接赋值公共字段 width/height（alpha(float) 存在，TextureCache.createSolid 存在于 com.watabou.gltextures）。

- WndBag 滚动修复（最终版本）：包装 `ScrollPane(itemsGrid)`，关键顺序——必须先 `resize(windowWidth, windowHeight)` 把 Window.camera 放到正确屏幕位置，再 `new ScrollPane(itemsGrid)` 创建 content.camera，最后 `add(scroll); scroll.setRect(0, TITLE_HEIGHT, w, h-TITLE_HEIGHT)` 触发 layout 此时 cameraToScreen 才能算出正确 cs.x/cs.y。content.camera 拿 Window.camera 的 screen 坐标，itemsGrid 在内部 (0,0) 起步。placeItem 仍用 `y = row*(slotHeight+MARGIN)`（不带 TITLE 偏移），让第一行 slot 出现在 viewport 顶部 = WndBag local y=TITLE_HEIGHT = 紧贴 title bar 下面。itemsGrid.setSize 放在 placeItems 之前作为初值，由 placeItem 内的 Math.max 扩到实际总高。
- 教训2：setRect 触发 layout() 依赖 Window.camera 的 (x,y,zoom,scroll) 已就位。若 Window.camera 还没 resize（chrome 6×6 tiny camera），cameraToScreen 算出来的 cs.y 是错的，等下一帧 Window.resize 才生效，但 content.camera 不会自动刷新——这就是截图"slot 跑到下半屏"的根因（cs.y 大约多了 7-15 game units）。修法是把 resize() 调用提前到 ScrollPane 构造之前。
- 应用户要求改为完整闭合外圈：rebuildBorders 去掉 heroFOV 可见性过滤（原过滤导致视野边界处边框断裂），现按整个气团覆盖区绘制连续外轮廓（不受视野限制）。
- 截图反馈"点与点之间并没有相连"：边框曾作为 BlobEmitter 子节点，但 Emitter.update 每帧 emit 粒子，粒子添加到 children 列表末尾 → 画在边框之上 → 只见交叉角点（叠加更亮），中段被粒子覆盖。修复：抽出为独立 effects/BlobBorder.java（extends Group），在 GameScene.addBlobSprite 中 `borderColor!=0` 时 `gases.add(new BlobBorder(gas))`，加在 BlobEmitter 之后 → 边框 Group 整体绘制在所有气团粒子之上。同时线宽 1px→2px，alpha 0.6→0.85，并保留 Image 池复用。
- 第二个根因（"依旧只是每个角的点"）：noosa Image 直接给公共字段 width/height 赋值不会调用 updateVertices()，顶点保持构造时的 1×1 → 每个 Image 只渲染 1 像素点，角点因两线重叠更亮。正确做法：solid 纹理 Image（宽高 1×1）用 `scale.set(w, h)` 拉伸（Visual.draw 的矩阵含 scale）。
- 凹角缺口：两格对角相邻（凸形/凹形轮廓）时，横线只覆盖本格 x∈[x,x+size]、竖线只覆盖 y∈[y,y+size]，交叉处 t×t 小方块无覆盖 → 角上缺一点。修复：线段两端各外延 t（scale(size+2t, t)，起点 x-t / y-t）。
- 边框显示开关：接入 SPDSettings.辅助格子()（WndSettings 游戏设置里的实时 CheckBox），BlobBorder.update 每帧 `visible = SPDSettings.辅助格子()`，关闭时跳过重建，游戏内切换立即生效；TargetedCell.update 同样接入（SPDSettings 已有 import）。
- StatusPane 血/绿/蓝条缓冲失效：原实现每 2 秒跳一步（oldHP-=缓冲/1.11f）→ 跳变非平滑；且回血无分支，oldHP 不回升、加血后条卡旧值；scale 只在 2s 块内刷新。重写为每帧指数平滑：`k=pow(0.02f, Game.elapsed)`，掉值时 `old = cur + (old-cur)*k` 缓慢跟随、回值时立即跟上，scale 每帧刷新；法力条除零加 最大护甲>0 保护；删除 HP缓冲/绿缓冲/法力缓冲/时间 字段。注意：Image 尺寸本 fork 须用 scale.set 而非 width/height 赋值（见上）。
- BossHealthBar 同样接入指数平滑（k=pow(0.0175f, Game.elapsed)，用户指定系数）：原实现 0.33s 定时器无 时间=0 复位 → 0.33s 后每帧 oldhp-=缺口/1.11 ≈ 每帧掉90% → 缓冲形同虚设。assignBoss 换 boss 时重置 instance.oldhp/oldshield=0，避免继承上个 boss 残值；hp/shieldedHP scale 加 0..1 双向钳制。
- HealthBar（怪物头顶条）同样接入：值由 level() 推送（ratio 0..1），update 里用 oldHealth/oldShield（初值 -1 区分未初始化，0 是合法值）指数平滑后再取整像素宽度；layout() 仍用原值，update 每帧覆盖。
- HealthBar"缓冲没生效"根因：调用方 WndInfoMob.MobTitle 只在构造时 level(mob) 一次，窗口打开期间目标值从不更新 → 平滑无触发点。修复：MobTitle 持有 mob 字段并 override update() 每帧 health.level(mob)。另注：IconTitle.health(float) 在本 fork 无任何调用者（死代码），HealthBar 实际只有 WndInfoMob 一个活跃使用点。
- 后续踩坑：HealthBar.layout() 仍调用 Hp/Shld.size() 用原始值，覆盖 update() 的平滑结果。修复：layout() 只管 Bg/文本/alpha，Hp/Shld 尺寸完全交给 update() 用平滑值写。子类调用顺序 super.update()→layout() 现在 layout 不会反向覆盖平滑结果。
