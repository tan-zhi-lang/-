
## 2026-09-02 未来空间器物品消失bug
- 根因：onSelect 存入 Statistics.itemN 的是背包内原对象而非 detach 返回值，同堆叠二次放入导致两槽共用同一对象。
- 已按用户要求将 9 处 isEquipped/doUnequip/detach 分支统一改为 item.detachAll(backpack)，detachAll 会将整个物品从背包移除，引用重复问题随之消除。
- 跨存档刷物品：Statistics.reset() 与 restoreFromBundle() 均未清空 item1~item9 静态字段，静态残留被写入其他存档。
- 修复：Statistics.java reset() 增加 item1~item9=null；restoreFromBundle() 恢复前先置 null 再按 contains 恢复。
- 改为全局互通：item1~9 不再随各存档序列化，改为 未来空间器.saveGlobal()/loadGlobal() 读写全局文件 未来空间器.dat；Dungeon.saveGame 写入、loadGame/reset 读取。物品全局唯一，互通且不可复制。
- 时间回溯功能：Dungeon 新增 回合计数（Hero.act 自增）/回溯上限=3/备份回溯存档()/回溯元数据()/恢复回溯存档()，每20回合 GameScene.update 自动 saveAll+整文件夹快照到 回溯0~2 子目录（含 meta.dat 回合数/层数）。Hero.die 删除存档后可在 WndGame 新增"时间回溯"按钮打开 windows/时间回溯.java 选择快照恢复并 CONTINUE 重载。回合计数随 game.dat 序列化（回合计数x）。注意：死亡时 Rankings 已提交，回溯复活会留下一条死亡记录。
- 时间回溯入口调整：从 WndGame 移除（用户已删），改加到 GameScene.gameOver() 死亡界面（StyledButton 时间回溯按钮，位于 restart 与 menu 之间，menu 下移一位）。
- 时间回溯NPE修复：GamesInProgress.delete() 是缓存 put null（语义=存档已删），恢复存档后 check() 返回缓存 null 导致 InterlevelScene.create NPE；改用 setUnknown() 移除缓存强制重读。
- 时间回溯NPE二次修复：备份回溯存档() 被精简成只写 meta.dat 未复制 game.dat/depth 文件，恢复后存档为空 check() 返回 null；已补回复制逻辑（单文件夹 回溯/）。触发点已由用户改为 buffs/机制/每45回合备份.java（saveAll→备份，顺序正确）。
- 时间回溯NPE第三次修复：备份回溯存档() 再次只剩写 meta.dat（复制逻辑丢失），恢复后文件夹为空 check() 返回 null；已补回复制全部存档文件（排除 回溯/）到 回溯/ 的逻辑。
- 时间回溯一次性加固：备份回溯存档() 先 deleteDir 旧快照再全量复制并校验 game.dat（无则不留脏快照）；恢复回溯存档() 恢复前校验快照含 game.dat、恢复后校验 gameFile 存在；时间回溯窗口 meta 为空时提示并关闭，切换场景前再校验 check()!=null，彻底杜绝 InterlevelScene NPE。
- 回溯失败排查：1层自杀测试提示"快照不存在或已损坏"，原因是旧版备份只写过 meta.dat 的残留快照（无 game.dat）；回溯元数据() 已改为校验快照内 game.dat，无效快照自动 deleteDir 并提示无快照。快照在开局 45 回合后才首次生成。
- 回溯失败根因确认：窗口代码"先 check() 后 setUnknown()"，而死亡时 GamesInProgress.delete() 已在缓存 put null，check() 命中缓存直接返回 null → 永远失败。磁盘证据：game1/game.dat 已被恢复为完整文件。修复：恢复成功后先 setUnknown 清缓存再 check，通过才切场景。
- 新增每2400回合回档：Dungeon 三个方法（备份回溯存档/回溯元数据/恢复回溯存档）参数化快照名，无参重载默认"回溯"；新 buff actors/buffs/机制/每2400回合回档.java（act: saveAll+备份到"回档/"，spend 2400），HeroClass 开局施加；时间回溯窗口改为列出"回溯/回档"两个快照按钮。
