- 用户反馈：手机导入存档依然无效；不需要分"可导出/可导入"两个文件夹，导出/导入共用一个目录，导出覆盖旧内容，导入读取同一目录（自己导出的或别人复制过来的）。

- Desktop 行为不变：前两个路径足以命中 `SPD存档导出/当前存档/`。

### 存档工具 Android 14 沙箱兼容（回退双路径）
- **根因诊断**：build.gradle `appAndroidTargetSDK = 34 (Android 14)`，Android 14 沙箱禁止应用通过 `new File("/storage/emulated/0/...")` 读取 `/storage/emulated/0/Download/`、`/storage/emulated/0/Documents/` 等公共目录，即使 manifest 有 `READ_EXTERNAL_STORAGE` 也只能读 media 文件。
- **错误路径**：之前引入的 `System.getenv("EXTERNAL_STORAGE")` 走的就是这条路，必然 `Permission denied` 或 `listFiles()` 返回 null，导致 `定位导入目录()` 第 3 个分支永远命中失败。
- **修复**：utils/存档工具.java 删除整个 `公共根目录()` + `公共子目录` 数组 + 第 3 个分支的扫描逻辑，回到只用 libGDX 封装的 `Context.getExternalFilesDir / getFilesDir` 两个路径。
- **玩家用法**（手机端）：用文件管理器开启"显示 Android/data"，把 `当前存档/` 文件夹（含 game.dat / depth*.dat）放到 `Android/data/com.shatteredpixel.shatteredpixeldungeon/files/当前存档/`，游戏内点导入即可。
- **Desktop 用法**不变：导出/导入都走 `C:\Users\<user>\缝合像素地牢\当前存档\`。

## 黑铁匠 type=2(GNOLL) 卡回合分析（只分析未改码）
- 卡回合机制：Actor.process()（Actor.java:231，无 try/catch）里 `current` 永不清空 → GameScene.java:826 `!Actor.processing()` 永假 → actor 线程永不 notify/重建 → 永久冻结。
- 嫌疑1（最可能）：投石异步链。GnollGeomancer.java:95-108 / GnollSapper.java:117-130 phase-2 `spend(TICK); return !attacked`（attacked=true 返回 false，current 留在投石者身上），依赖飞石 MissileSprite 落地回调 GnollGeomancer.java:737-742 `source.next()` 清 current。static `rocksInFlight`(:677) 跨场景泄漏（飞石未落地时死亡转场/切场景，回调丢失计数残留）→ 之后每次投石计数减不到 0 → next() 永不执行 → 卡死。
- 嫌疑2：actor 线程静默死亡——GNOLL 链路任何未捕获异常（doRockThrowAttack 在 actor 线程操作 MissileSprite :695；carveRockAndDash :399-432 在 actor 线程调 GameScene.updateMap/Fog）→ 线程死 + current 残留，同效。
- 嫌疑3：双重死亡——GnollGeomancer.java:289 手动 `if(!isAlive())死亡时` 与 Char.java:1541-1543 Char.受伤时 内部自动死亡触发重复，最终血段 HP=0 时 死亡时 执行两次（掉落/统计重复，非幂等操作污染回合）。
- 次要：MineLargeRoom.java:116-118 guard 生成 do-while 与 :125-131 路障 i-- 回退循环，唯一空地被占时生成期死循环（进图卡死，非卡回合）。
- 修复方向：rocksInFlight/knockedChars 层切换重置；Actor.process 包 try/catch 异常时 current=null；删除 :289 手动死亡（Char.受伤时 已有）；生成循环加上限。

## 搜索拾取连通性修复（Hero.search 自动拾取）
- 用户反馈：`search()` 自动拾取会把"英雄过不去的地方"也拾取（隔水/隔坑、门后/锁后、被怪挡路）。
- 根因：`Hero.java:10483` 原判定 `!solid && visited && cellIsPathable(curr)` 只校验**目标格本身**，不校验**从英雄当前位置到目标格的路径连通性**；`visited` 只是曾见过（FOV 历史），不等于现在能走过去。
- 修复（最精简）：`Hero.java` 新增 `计算搜索可达()`（从 `pos` 做 4 邻接 BFS，带行边界防越行）+ `可搜索踏()`（单格可踏判定，复用 cellIsPathable 同款规则：passable / 飞行·Amok / 体型 / 占用）；`search()` 循环前预计算 `搜索可达阵`，判定追加 `&&搜索可达阵[curr]`。
- 文件内已验证：方法在 10387-10414，预计算在 10437，判定在 10483。未跑完整 Android 构建，建议本地 `./gradlew build` 确认。
### 自残绳 CME 修复（9.3/10:50 版崩溃）
- 崩溃：ConcurrentModificationException @ 用品.自残绳.使用，HashMap$KeyIterator。
- 根因：自残绳.java 遍历 Dungeon.level.mobs（HashMap）时，m.受伤时() 使怪死亡被移出 map → CME。

### GnollGeomancer rocksInFlight 卡回合修复
- 根因：rocksInFlight/knockedChars 为 static，切层时 MissileSprite 销毁、回调丢失 → 计数残留 >0 → source.next() 永不执行 → actor 线程 current 永不清空 → 永久卡回合。
- 修复（GnollGeomancer.java）：新增 static Level flightLevel；doRockThrowAttack 入口检测 flightLevel != Dungeon.level 时重置计数并 clamp Math.max(0)；回调内 flightLevel != Dungeon.level 时直接 return，防止旧层回调污染新层计数。
- 注意：不要把重置放构造器——难度计算 `Dungeon.难度攻击(new GnollGeomancer())`（约 :713）会在回调内构造临时实例，会误清计数。
- 未修（同前分析）：Actor.process 无 try/catch；:289 手动死亡重复触发；MineLargeRoom 生成循环无上限。
